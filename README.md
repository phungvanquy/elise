# Elise Rust core

This directory contains the Elise Rust backend used by the V2bX VLESS, VMess, AnyTLS, and Hysteria 1/2 installer. It builds as a separate executable and runs as a separate systemd service for each panel node.

The source was imported from [`phungvanquy/Elise-Backend`](https://github.com/phungvanquy/Elise-Backend) at commit `b152c13beaa87192951900e5f77ea9d055928f83` (`v1.0.1`). The Rust source retains its [PolyForm Noncommercial 1.0.0 license](LICENSE); the V2bX Go source retains its repository license.

From the V2bX repository root:

```bash
cargo test --locked --all --manifest-path rust/elise/Cargo.toml
cargo build --locked --release --manifest-path rust/elise/Cargo.toml
```

The V2bX release workflow packages Linux amd64 and arm64 builds alongside the Go archives. The installer downloads the Elise asset from the same V2bX release.

Pass an optional panel platform after the node ID, for example `V2bX elise add anytls 70 xiaov2board`. Supported platforms are `xboard` (default), `v2board`, `xiaov2board`/`xiaov2b`, `ppanel`, and `sspanel`/`sspanel-uim`. The installer uses `elise panel-info --config <path>` for the other platforms so preflight and the running service use the same API client. The command reports only protocol, port, TLS mode, version, and whether REALITY keys are present. A configured `panel_node_type` validates the returned protocol on every refresh; PPanel selects a matching enabled protocol. A platform's API must expose the requested protocol.

Use `V2bX elise add <vless|vmess|anytls|hysteria|hysteria2> <node-id>` to configure a node. `hysteria1` and `hy1` map to the panel type `hysteria`; `hy2` maps to `hysteria2`. TLS nodes offer existing PEM files, automatic Let's Encrypt HTTP-01, or a persistent self-signed certificate. See the [installer certificate modes](../../README.md#elise-rust-core-for-vless-vmess-anytls-and-hysteria-12) for requirements and renewal behavior. Hysteria uses UDP listeners, including startup checks. Panels returning `version=2` for a `hysteria` node select the Hysteria 2 inbound automatically.

For native configuration, `cert_mode=http` (alias `acme`) enables automatic HTTP-01 issuance; set `cert_domain`, `acme_email`, `cert_file`, and `key_file`. The wizard uses `acme_server=letsencrypt` and `cert_key_length=ec-256`. The responder supports IPv4 and IPv6, waits up to two minutes for another instance to release TCP port 80, and bounds an issuance attempt to four minutes. Every 12 hours, Elise checks the certificate's expiry, hostname, and matching private key. Successful renewal reloads the inbound independently of panel availability; this may disconnect active sessions. Failed renewal retains a still-valid certificate. An unusable certificate at first startup stops the node.

`cert_mode=file` uses supplied files. A self-signed certificate generated by the wizard also uses file mode, preserving its identity across restarts. `auto_tls` is a separate fallback that generates a self-signed certificate in memory; it is not ACME. The wizard sets `auto_tls=false` in all three modes. DNS-01 is not implemented.
